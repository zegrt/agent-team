# Inbox: team corrections from projects

A project's manager drops a correction here when it is about team process and true on any project with any director.
Motion craft, a director's taste or a project-only rule go elsewhere (the project's own flow, the director's profile,
the project's board).

1. The manager who hears the correction writes it on its own board first, as a dated decision. It takes effect there
   at once, because the board outranks the skill.
2. If it is general, that manager adds one new file here, named `<date>-<project>-<short-name>.md`, with:
   - the date and the director's words;
   - where it happened (project, task, what went wrong);
   - which card or template field it should change, or "new".
   New files only, so two managers never edit the same file.
3. Only the skill's own manager edits SKILL.md, RULES.md and the templates, after the director approves. It adds a test
   scenario for the change, deletes the inbox file, and tells the projects to pull.
4. Once the skill holds the rule, each project's manager deletes its own board line, or keeps it as a tightening if the
   project needs more.

A correction that is half team process and half something else is split, and each half filed where it belongs.
